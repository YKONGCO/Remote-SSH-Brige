# 文件传输、故障恢复与 MCP 精简

## 这次改进针对的问题

`.artifacts/操作记录.json` 包含 94 条失败标记记录，包含同一任务的重复查询，不能用于推算整体失败率。按任务 ID 去重，有 19 个上传任务因超时失败；目录查询有 14 次连接阶段失败、8 次执行阶段失败。另有 `date -Is` 误拦截、并发上限直接拒绝任务，以及失败传输的查询摘要显示“完成”的问题。

现在只读文件查询对暂时性网络故障最多重试两次；命令执行、文本写入和删除不自动重放。时间查询参数按明确列表校验，修改时间的参数仍会被拒绝。

## MCP 调用方式

`list_servers` 只返回服务器的 `id/name/host/root`。完整权限和命令白名单不再重复附在每台服务器后面。

需要时调用 `server_info`：

```json
{ "server_id": "SERVER_ID", "topic": "permissions" }
```

`topic` 可为 `permissions`（默认）、`transfers`、`commands`。传输主题包含本地目录授权、大小限制和默认传输设置；命令主题才返回完整命令规则。工具列表保持稳定，权限在执行时检查。

运行时错误返回一个简短 JSON，包含 `code/message/retryable`，必要时附 `hint`、缺少的权限或部分执行结果。完整诊断保留在审计记录中。参数反序列化错误仍以简短参数说明返回；未知工具属于协议级错误。成功的查询不代表底层任务成功，仍须检查 `status/exit_code`。

## 单文件与批量传输

`upload_file`、`download_file` 仍使用 `server_id/local_path/remote_path/overwrite?`。本地路径属于运行应用的电脑。可选 `request_id` 用于调用方重试：相同 ID 和参数返回同一任务，不重复创建；同一 ID 更换参数会被拒绝。

`transfer_batch` 接收 `direction`、`items` 和可选 `recursive/overwrite/skip_existing/request_id`：

```json
{
  "server_id": "SERVER_ID",
  "direction": "download",
  "items": [
    {
      "remote_path": "/workspace/results",
      "local_path": "D:/Downloads/results"
    }
  ],
  "recursive": true,
  "skip_existing": true
}
```

返回 `group_id` 和各子任务结果。一次最多 100 个入口，展开最多 1000 个文件和目录，深度最多 64 层；递归不跟随符号链接。空目录也会创建。每个子任务独立检查权限、审批、源文件变化和目标冲突。相同内容通过 SHA-256 校验后跳过；内容不同仍遵循覆盖设置。批次按文件提交，不提供整个目录的原子替换。批次失败时已创建的目录可能保留。

桌面端保留单文件原生选择器，并增加批量上传、上传文件夹和下载文件夹。新增桌面传输入口同样先由原生选择器获取路径。

## 断点、重试和提交

传输任务及检查点保存在 SQLite schema v4；v2/v3 自动迁移。升级后旧应用无法打开 v4 数据库。

文件字节只通过 SSH/SFTP 与磁盘文件流传输，不进入 MCP、前端 IPC 或审计。临时文件位于目标目录，名称为 `.remote-ssh-brige-<transfer_id>.part`。检查点保存源文件身份和分块摘要，不保存文件正文。

恢复时重新验证权限、服务器身份、源文件和保留的数据块。损坏或尚未确认的尾部回退到最后一个验证通过的块。上传恢复还会比对本地源文件前缀；下载恢复完成后重新核对远端内容。完成前计算 SHA-256，上传还会读回远端临时文件进行验证，因此需要额外读取流量。校验通过后才提交正式路径。

网络超时与连接中断使用指数退避和随机抖动重试，默认最多 5 次。重试后的 I/O 窗口缩小，以减少弱网下的大块阻塞。权限拒绝、空间不足、源文件变化和主机指纹异常停止重试。提交阶段结果不明确时停止；手动重试会先核对目标摘要，已成功提交的文件直接确认完成，不再次覆盖。

应用重启后，中断任务恢复为“已暂停”，点击继续后重新校验。暂停或失败保留临时文件；取消停止自动传输，也保留临时文件以便显式清理。成功记录保留 7 天，失败或暂停记录保留至清理；任务记录总数上限 1024。远端临时文件清理走正常删除权限、删除保护和审批。

## 控制与默认设置

`transfer` 支持 `list/read/cancel/pause/resume/retry/cleanup/configure`。`configure` 可调整 `priority`（-10 至 10，越大越优先）和 `bandwidth_kib`（0 跟随默认值）。`read` 延续原有 `version/wait_secs` 长轮询方式；暂停会结束等待。

默认同时运行 4 个任务，每个主机最多 2 个；同一主机、端口和用户的别名共享并发限制。其他任务排队。设置中可以调整并发、重试、I/O 超时、无进度超时和默认限速。限速按任务计算，校验读取流量不计入该限速。全局默认限速与任务限速都非零时取更小值。

界面显示排队、重试、暂停、校验和提交阶段，以及剩余时间、重试次数、下次重试时间、复用的断点字节和文件摘要。

## 验证

`npm run test:ui`、`npm test` 和 `npm run test:e2e` 验证界面、后端与真实 MCP→Rust→SSH/SFTP 测试链路。传输故障测试使用本地临时测试服务，不连接用户服务器；覆盖双向断线、部分进度恢复、暂停继续、进程重启、请求去重、递归批次、校验和并发排队。大文件大小边界另用超过 4 GiB 的临时文件验证。

可选的多连接分块下载和 HTTP/HTTPS 下载源不属于默认传输路径。当前版本统一通过 SFTP 完成传输，不依赖远端安装额外程序。
